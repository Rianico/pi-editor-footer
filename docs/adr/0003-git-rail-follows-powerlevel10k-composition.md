# Git rail follows powerlevel10k's composition, not our own catalogue

The footer's git segment was a starship-flavoured catalogue — `branch [=1 !3 ?5 ↑2]` — with brackets, a count on every glyph, ahead before behind, no branch icon, and a porcelain-v1 parse that lost the branch name entirely on a diverged branch (`main...origin/main [ahead 1, behind 2]` never matched `src/git.ts`'s regex) and on `[gone]`, while a detached HEAD rendered a bare `HEAD` because `readGitStatus` was always called without options, so no oid was ever read. Compared against the two rails we could copy — pi-atelier's flag-only ` main*` and powerlevel10k's ordered count parts — our shape was neither: noisy to scan at a 1 s refresh, and too lossy to trust. We adopt **powerlevel10k's composition** — `[COMMIT] [BRANCH] [TAG] [STAGED] [UNSTAGED] [UNTRACKED] [BEHIND] [AHEAD] [STASH] [ACTION]`, single-space separated, no brackets, counts suppressed at 1, stash always counted, conflicts signalled by colour rather than a glyph — while keeping this repo's existing nerd/ascii glyph vocabulary, and we replace the porcelain-v1 parse with a single `git status --porcelain=v2 -z --branch --untracked-files=all` read.

Status: accepted

## Considered Options

- **pi-atelier's flag-only rail (` main*`)**: calmest and cheapest by far (6 columns, one spawn), but atelier's git detail lives in a sidebar this extension does not have; dropping ahead/behind removes the one fact a coding agent acts on (push, pull, rebase), and an untracked-only tree would look clean.
- **starship's default (`[!?+⇡1]`)**: the same family we already had — its per-category flags without counts still need counts to be useful, and its bracket group is what made the rail noisy in the first place.
- **Keep ours, restyle only**: leaves the porcelain-v1 defects (diverged and `[gone]` branches lose their name, detached renders bare `HEAD`) and the dead `readCommit`/`readTag`/`readCounts` options in place — a restyle on top of a parser that cannot see the states being restyled.
- **powerlevel10k composition (chosen)**: the ordered, optional-count parts read left to right as "which branch, what changed, where it stands". Suppression at 1 removes most of the noise while keeping `3` visible when it matters. Costs nothing extra in subprocesses: one read covers branch, counts and divergence.
- **powerlevel10k's own icon set** (FontAwesome circles `\uF055`/`\uF06A`/`\uF059`, branch `\uE220`): rejected. p10k ships seven icon modes precisely because no toolkit agrees; this repo already has a tested nerd/ascii pair and a theme-aware glyph layer. We took the composition, not the codepoints — and swapping to p10k's icons later is a one-file edit in `src/icons.ts`.

## Consequences

- `GitStatus` shrinks to exactly what the rail draws: `branch`, `commit{oid, tag}`, `staged`, `unstaged`, `untracked`, `stashed`, `behind`, `ahead`, `unmerged`. `deleted` and `renamed` fold into the staged/unstaged file counts (as gitstatus does), `modified` disappears as a kind, `⇕` (diverged) is no longer a glyph, and `hasGitChanges` plus the three dead options are deleted.
- **Conflicts are colour-only**: while `unmerged > 0` the branch paints `error`, with no glyph and no count. Accepted trade-off: a monochrome theme, or a conflict that appears without an operation (a failed `git stash pop` leaves unmerged entries and no `MERGE_HEAD`), degrades to no visible signal. Every operation-driven conflict is still covered by the action label below.
- **In-progress operations render instead of the counts**: `|MERGING`, `|REBASE 2/7`, `|CHERRY-PICKING`, `|REVERTING`, `|AM`, `|BISECTING` — git-prompt.sh's uppercase vocabulary, not p10k's lowercase words — detected from `git rev-parse --git-path` marker paths and their progress files. While an action is live the staged/unstaged/untracked/divergence/stash parts are suppressed (p10k's rule: during an operation those counts are the operation's own churn, not the user's work). This is what makes "all conflicts resolved and staged, merge not committed" visible at all; a second spawn, batched into one `rev-parse` call, pays for it.
- **The three segment toggles split identity from decoration** — `gitBranch` gates the branch, or the short commit sha when detached; `gitStatus` gates the counts and the action label; `gitCommit` gates only the tag shown beside the sha (it was dead before, since no caller passed `readCommit`). Keeping `gitCommit`'s stored default `false` therefore hides nothing important, and no config migration is needed. *(Amended after #45: the first implementation flipped this toggle's default instead, which would have hidden the sha for every config saved while the toggle was inert.)*
- **Tags render only while detached**; p10k's `REMOTE_BRANCH` part (upstream configured to a differently-named branch) is out of scope.
- **ascii mode loses the branch icon** (p10k's ascii set has none), which also clears the collision between our ascii git glyph `*` and a dirty marker.
- `docs/specs/06-git.md`, `docs/specs/05-footer.md`, the AGENTS.md footer block and this repo's glossary describe the old catalogue and must be re-aligned with this ADR.
